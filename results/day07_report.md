# День 7 — Финализация mini-product

Проверено 30 октября 2026 года. Проект оформлен как CLI-продукт:
принимает текст, выполняет пять LLM-этапов с маршрутизацией и guardrails,
сохраняет структурированный JSON и показывает ход обработки.

## Что сделано

1. README переписан под пользователя продукта: назначение, Python/uv,
   установка из lock-файла, настройка ключа и провайдера, реальные команды,
   пять сценариев, вход/выход, структура, ошибки, ограничения и проверка.
2. Предыдущее описание экспериментов сохранено в
   `docs/development-history.md`. Результаты предыдущих дней не удалялись.
3. Подготовлена папка `demo/`: инструкция, пять входов и записанные ответы
   этапов в `scenarios.json`, полный пример выхода в `output.json`.
4. Добавлены `src/itg_llm/demo.py`, CLI `itg-llm-demo` и `make demo`.
   Можно запустить все пять сценариев или выбрать один через `--scenario`.
5. Основной CLI теперь понятно обрабатывает отсутствующий входной файл,
   неверный JSON разметки, неизвестные категории в разметке и ошибки
   сохранения результата. Ввод проверяется до создания API-клиента.
6. Дополнительные CLI сравнения также обрабатывают ошибки чтения/записи.
   При ошибках обработки они возвращают ненулевой код завершения.
7. Добавлены тесты демо и ошибок CLI. Исправлен устаревший тест,
   требовавший вводный docstring пакета, который ранее был удалён.
8. Проверены установка в чистое окружение, entry points, демо и все
   проверки проекта. Локальная установка обновлена, новая CLI доступна.

## Пять сценариев

| Имя | Категория | Что демонстрирует |
|---|---|---|
| support | support | Нумерованные шаги и запрос недостающих данных |
| complaint | complaint | Эмпатию и действия при задержке заказа |
| sales | sales | Краткость, следующий шаг, отсутствие выдуманных цен |
| feedback | feedback | Благодарность с конкретной деталью |
| question | general_question | Прямой ответ начинающему разработчику |

Во всех пяти сценариях выполняются настоящий pipeline, Pydantic-валидация,
выбор маршрута, ограничения, приоритеты, трассировка и сборка JSON.
Ответы LLM-этапов, включая классификацию и самопроверку, подготовлены
вручную. Это демонстрация интерфейса и механики приложения без сети,
а не оценка качества модели. JSON содержит `mode: recorded_demo`.

Реальный режим для произвольного текста остаётся отдельной командой
`itg-llm` с ключом из `.env` и вызовами настроенного API.

## Как показать проект

Из корня репозитория:

```bash
uv sync --locked
uv run itg-llm-demo
```

Для живой модели настройте `.env` и выполните:

```bash
uv run itg-llm --file examples/08_support.txt --output results/support_live.json
```

Для проверки устойчивости и качества кода:

```bash
make check
```

## Границы проверки

В день 7 новые запросы к внешнему LLM API не выполнялись. Уже находившийся
в проекте `results/day06_live.json` сохранён без изменений: в нём 9 из 10
текстов обработаны, один завершился таймаутом; классификация верна для 7
из 9 обработанных. Это существующий результат, а не новый успешный прогон.

Демо не подтверждает семантическое качество модели и доступность
провайдера. Формат и длина проверяются кодом, но self-check и правильность
классификации зависят от модели. Отрицательный self-check после одной
доработки сохраняется в результате и сам по себе не меняет код CLI на 1.

Публикация, push и commit не выполнялись. Существовавшие изменения
пользователя сохранены.
